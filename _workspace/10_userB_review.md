| "준비 중" 항목들 | **제거** | 일일 리마인더, 자동 삭제, 개인정보 처리방침, 이용약관, 의견 보내기 -- 5개 메뉴가 전부 "준비 중". 구현되지 않은 메뉴를 보여주는 것은 미니멀리즘의 반대편이다. |

### 1-3. 정보 과부하 판단

**TodoItem이 가장 심각하다.** 하나의 카드에 다음이 동시에 표시될 수 있다:
- 체크박스 + 제목 + 색상 왼쪽 바
- 날짜 배지 + 카테고리 칩 + 서브태스크 배지 + 반복 배지
- 삭제(X) 버튼 + 확장 화살표
- (확장 시) 메모 입력 + 서브태스크 목록 + 서브태스크 추가 입력 + 이동 버튼 + "속성 편집" 링크

**카드 하나에 최대 11개의 인터랙션 포인트가 있다.** 이건 미니멀이 아니다.

## 2. 핵심 기능 완성도 (각 1~5점)

### 할일 추가/완료/삭제 -- 4.5/5
QuickAddBar가 화면 하단에 항상 있고, 텍스트 입력 후 엔터 또는 버튼 탭으로 즉시 추가된다. 완료는 체크박스 1탭. 삭제는 X버튼 + 확인 다이얼로그 2탭. 빠르고 직관적이다. 유일한 감점은 할일 추가 시 카테고리나 마감일을 같이 지정할 수 없다는 점 -- QuickAddBar가 제목만 받는다. 추가 후 상세시트를 열어야 한다.

### 서브태스크 -- 4/5
카드 확장 후 인라인 추가가 잘 동작한다. 토글/삭제도 깔끔하다. 감점: 서브태스크 제목 수정이 인라인에서 불가능하다 (store에 updateSubtask이 있지만 UI에서 호출하지 않음). 서브태스크 순서 변경도 store에 reorderSubtasks가 있지만 UI에서 불가능하다.

### 카테고리 -- 4/5
생성/수정/삭제 + 아이콘/색상 선택이 모두 있다. CategoryEditor가 Modal로 동작해서 접근성이 좋다. 감점: 카테고리 순서 변경 불가. 할일을 드래그해서 다른 카테고리로 이동 불가.

### 캘린더 -- 3.5/5
월간 그리드 + 날짜별 할일 목록. 기본기는 충실하다. 감점: (1) 날짜에 dot 하나만 표시되어 할일 개수를 알 수 없다, (2) 월 이동 시 선택 날짜가 유지되지 않고 오늘로 돌아오지도 않아서 빈 상태가 보인다, (3) 스와이프로 월 이동 불가 -- 좌우 화살표만 있다.

### 검색 -- 3/5
오늘 탭에만 있다. 제목+메모 대상 필터링이 동작한다. 감점: (1) 전체 할일 검색이 아닌 오늘 할일만 검색, (2) 카테고리 탭/캘린더 탭에는 검색이 없다, (3) 완료된 할일 검색 불가.

### 반복 할일 -- 3.5/5
매일/매주/매월 반복 설정이 TodoDetailSheet에서 가능하다. 완료 시 자동으로 다음 회차가 생성된다(todoStore:121-147). 감점: (1) 특정 요일 반복(매주 월,수,금) 불가 -- type에 'custom'이 있지만 UI에서 선택 불가, (2) 반복 종료일 설정 불가, (3) QuickAddBar에서 반복 설정 불가.

### 색상/마감일/메모/정렬 -- 3.5/5
- **색상**: 동작하지만 21개는 과도하다. 할일 왼쪽에 4px 바로 표시되어 시각적 효과는 좋다.
- **마감일**: 오늘/내일/이번주 토/다음주 월 + 직접 입력. 직접 입력이 텍스트(yyyy-MM-dd) -- DatePicker가 아닌 건 불편하다. 형식 틀리면 그냥 무시된다.
- **메모**: 인라인 편집, 300ms 디바운스 자동저장. 잘 동작한다.
- **정렬**: 위/아래 화살표로 수동 정렬. 기능적이지만 원시적이다. 드래그 앤 드롭이 없다.

## 3. 인터랙션 효율성

### 3-1. 탭 수 분석

| 작업 | 탭 수 | 평가 |
|------|-------|------|
| 할일 추가 | 1 (포커스) + 타이핑 + 1 (전송) = **2탭** | 우수 |
| 할일 완료 | **1탭** (체크박스) | 최고 |
| 할일 삭제 | 1 (X버튼) + 1 (확인) = **2탭** | 적절 |
| 카테고리 변경 | 1 (카드 확장 또는 롱프레스) + 1 (속성 편집) + 1 (카테고리 선택) = **3탭** | 아쉬움 |
| 마감일 변경 | 1 (롱프레스로 시트 열기) + 1 (날짜 선택) = **2탭** | 적절 (단, 롱프레스 발견이 어려움) |
| 서브태스크 추가 | 1 (카드 확장) + 타이핑 + 1 (엔터) = **2탭** | 적절 |
| 메모 추가 | 1 (카드 확장) + 타이핑 = **1탭** | 우수 |

### 3-2. 발견하기 어려운 인터랙션 (큰 문제)

1. **롱프레스로 상세시트 열기** (TodoItem.tsx:123 `onLongPress`)
   - 카드를 탭하면 확장/축소, **롱프레스**하면 상세시트가 열린다.
   - 이것을 알려주는 UI 힌트가 전혀 없다. 온보딩도 없다.
   - 확장 패널 안에 "속성 편집" 링크가 있긴 하지만, 카드를 한 번 확장해야만 보인다.
   - **치명적**: 사용자가 마감일/카테고리/반복/색상을 설정하는 방법을 모를 수 있다.

2. **카드 확장** (TodoItem.tsx:71-73 `handleMainPress`)
   - 카드를 탭하면 서브태스크/메모 패널이 열린다는 것도 명시적 안내가 없다.
   - 확장 화살표 아이콘이 있지만 크기 20px, 색상이 textDisabled여서 거의 안 보인다.

3. **테마 토글** (settings.tsx:141-144)
   - 테마 변경이 탭할 때마다 light -> dark -> system 순환이다.
   - 현재 값만 보이고 선택지를 미리 볼 수 없다. 세 번 탭해야 원래로 돌아온다.

4. **자동 삭제 일수 토글** (settings.tsx:148-151)
   - 0 -> 7 -> 14 -> 30 -> 60 -> 90 순환. 6번 탭해야 원래로 돌아온다.
   - "준비 중" 기능인데 값이 변경된다 -- 혼란스럽다.

## 4. 코드에서 발견한 문제점

### 4-1. 실제 동작하지 않을 가능성이 있는 코드

**[P1] TodoDetailSheet -- BottomSheet 초기화 타이밍 문제**
- `TodoDetailSheet.tsx:96`: `if (!todoId || !todo) return null;` -- 이 경우 BottomSheet 컴포넌트가 아예 마운트되지 않는다.
- 하지만 부모에서 `selectedTodoId && <TodoDetailSheet ...>`로 조건부 렌더링하고 있어서 (today.tsx:277-281), 시트가 열릴 때 BottomSheet가 새로 마운트된다.
- `@gorhom/bottom-sheet`는 마운트 시 index 0으로 열리지만, **unmount -> remount 패턴은 애니메이션이 깨질 수 있다.** 열림/닫힘을 ref.close() 대신 조건부 렌더링으로 관리하는 것은 권장 패턴이 아니다.

**[P1] currentStreak 무한루프 가능성**
- `today.tsx:62`: `while (true)` 루프가 streaks 객체에 데이터가 계속 있으면 수년간 순회할 수 있다.
- streak 데이터가 매일 쌓이면 365일 * 수년 = 수천 번 반복. 성능은 문제없을 수 있지만 방어적 코딩이 아니다.
- 동일한 패턴이 `todoStore.ts:518-534`에도 있지만 여기서는 `subDays` 유틸을 사용하여 조금 더 안전하다.

**[P2] 카테고리 카드 width: '47%'**
- `all.tsx:424`: `width: '47%'`는 gap 12와 결합해서 정확히 맞지 않을 수 있다. `flexBasis` + `flexGrow` 패턴이 더 안정적이다. 특정 화면 크기에서 3번째 카드가 다음 줄로 밀리지 않고 2개만 표시되는 건 의도적이지만, gap을 포함한 정확한 계산이 아니다.

**[P2] Recurrence 비교 로직**
- `TodoDetailSheet.tsx:309-310`: `todo.recurrence?.type === opt.value?.type`으로 비교하는데, interval이 다른 경우(매주 1회 vs 매주 2회)를 구분하지 못한다. 현재 UI에서 interval은 항상 1이라 문제없지만, 타입 안전성이 부족하다.

### 4-2. 웹/네이티브 호환성 문제

**[P1] expo-haptics 웹 미지원**
- `CheckBox.tsx:34`: `Haptics.impactAsync()` -- expo-haptics는 웹에서 지원되지 않는다. Platform.OS 체크 없이 호출하면 웹에서 에러가 발생하거나 무시된다. Expo SDK가 자동으로 no-op 처리하긴 하지만 콘솔 경고가 나올 수 있다.

**[P1] @gorhom/bottom-sheet 웹 호환성**
- `TodoDetailSheet.tsx`에서 `@gorhom/bottom-sheet`를 사용하는데, 이 라이브러리는 React Native 네이티브 전용이다. 웹에서는 동작하지 않거나 크래시할 수 있다. Expo Web을 지원하려면 웹용 대체 구현이 필요하다.

**[P2] window.confirm / window.alert**
- `settings.tsx:165`, `TodoItem.tsx:85`: `Platform.OS === 'web'` 분기로 `window.confirm`을 사용하는 것은 올바른 접근이지만, 웹에서 Native Alert를 방어하는 패턴이 모든 곳에 일관되게 적용되어 있는지 확인 필요. 현재 코드상으로는 Alert 사용처가 모두 분기 처리되어 있어 양호하다.

### 4-3. 데이터 유실 가능성

**[P1] 소프트 삭제만 있고 하드 삭제가 없다**
- `todoStore.ts:162-175`: deleteTodo가 `is_deleted: true`만 설정한다. 실제 배열에서 제거하지 않는다.
- 시간이 지나면 todos 배열이 무한히 커진다. AsyncStorage의 용량 제한(Android 6MB 기본)에 도달하면 **persist가 실패하고 전체 데이터가 날아간다.**
- autoDeleteDays 설정이 "준비 중"이므로 자동 정리 로직이 없다.

**[P2] 데이터 초기화가 너무 쉽다**
- `settings.tsx:154-159`: doReset이 todos, categories, dailyFocus, streaks를 모두 빈 배열/객체로 설정한다. 2중 확인을 하긴 하지만 백업/내보내기 기능이 없다. 실수로 초기화하면 복구 불가.

**[P2] Zustand persist 직렬화 한계**
- todos 배열 안에 subtasks 배열이 중첩되어 있고, recurrence 객체도 포함된다. 데이터가 커지면 JSON 직렬화/역직렬화 비용이 매 상태 변경마다 발생한다. 할일 100개 이상이면 체감 성능 저하 가능.

### 즉시 개선 (1주 이내)
1. 준비 중 메뉴 5개 전부 숨기기 (일일 리마인더, 자동 삭제, 개인정보, 이용약관, 의견)
2. statsBar 오늘 탭에서 제거 (또는 설정에서 끌 수 있게)
3. 롱프레스 없이 상세시트 접근 가능하게 -- 확장 패널의 "속성 편집"을 더 눈에 띄게 하거나, 카드 오른쪽에 ... 메뉴 추가

5. dailyFocus/priority 관련 죽은 코드 제거

3. 마감일 입력에 DatePicker 사용
4. 카테고리 뷰에 리스트/그리드 전환 옵션
