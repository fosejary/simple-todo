# MVP Audit Skill

MVP 코드베이스의 프로덕션 준비도를 체계적으로 평가하고 작업 우선순위를 도출한다.

## 감사 프로세스

### 1. 코드베이스 스캔
- 프로젝트 루트에서 파일 구조 파악 (`app/`, `components/`, `lib/`, `hooks/`, `stores/`)
- `package.json` 분석: 의존성 버전, 보안 취약 패키지 확인
- TypeScript 설정 검토 (`tsconfig.json`: strict 모드 여부)

### 2. 코드 품질 분석
- 에러 핸들링: try-catch 유무, 사용자 대면 에러 메시지, 글로벌 에러 바운더리
- 타입 안전성: `any` 사용 빈도, 타입 캐스팅, 미정의 타입
- 코드 중복: 반복 패턴 식별
- 미사용 코드: import 되었지만 사용되지 않는 모듈

### 3. 보안 감사
- Supabase RLS: 모든 테이블에 RLS 활성화 여부, 정책 적절성
- 인증: 토큰 저장 방식, 세션 관리, 보호 라우트 적용
- 입력 검증: 사용자 입력의 검증/새니타이즈
- 환경변수: 하드코딩된 키/시크릿 여부, `.env` 관리
- API 보호: 인증되지 않은 접근 차단

### 4. 성능 분석
- 번들 크기: 불필요한 대형 패키지
- 렌더링: 불필요한 리렌더, memo 미사용
- 리스트: FlatList/FlashList 사용 여부, 가상화
- 이미지: 최적화 미적용 이미지
- 네트워크: N+1 쿼리, 미캐싱 반복 요청

### 5. 누락 기능 분석
- 에러 상태 UI (빈 상태, 로딩, 에러)
- 오프라인 처리
- 접근성 (a11y)
- 로깅/모니터링
- 국제화 (i18n) 준비도

### 6. Phase 2 기능 재평가
- `_workspace/03_design_mvp.md`의 Phase 2 목록 검토
- 현재 코드베이스 기반 구현 난이도 재산정
- 사용자 추가 요구사항과 병합
- 우선순위 재설정 (사용자 가치 × 구현 용이성)

### 7. 우선순위 매트릭스 생성

```
| 항목 | 영향도 | 난이도 | 담당 에이전트 | 우선순위 |
|------|--------|--------|-------------|---------|
| RLS 정책 보완 | 높음 | 낮음 | production | P0 |
| 에러 바운더리 | 높음 | 낮음 | production | P0 |
| 리스트 가상화 | 중간 | 낮음 | performance | P1 |
| Phase 2 기능 X | 높음 | 중간 | feature | P1 |
| 분석 계측 | 중간 | 중간 | growth | P1 |
| ... | | | | |
```

- P0: 반드시 해결 (보안, 크래시 유발)
- P1: 높은 가치 (사용자 경험, 비즈니스)
- P2: 있으면 좋음 (개선, 최적화)
